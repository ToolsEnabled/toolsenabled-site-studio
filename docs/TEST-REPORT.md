# Site Studio 0.1.0 test report

On 2026-10-01, a Linux verification run passed **171/171 tests in 11 files**, with zero failures, skips or cancellations, in 27.29 seconds. It used Node.js 22.19.0 and headless Chromium with DISPLAY unset. The suite also passed **171/171** from a fresh ZIP extraction. See [TESTING.md](TESTING.md) for reproduction commands, optional screenshots and lifecycle records, and reproducible archive checks.

**The recorded browser run required Chrome's sandbox to be disabled in its container.** It explicitly used SITE_STUDIO_CHROME_NO_SANDBOX=1, which adds --no-sandbox and --no-zygote. These results do not verify Chrome sandbox behavior. Without that opt-in, the test harness leaves both sandboxing and the zygote enabled. Browser shutdown is bounded and completes before the other test HTTP servers close.

The suite exercises real stdio processes, two-page editing and confirmed export, browser controls, session isolation, preview capabilities, storage and validation failures, and deterministic archives. The lifecycle preserves original and binary bytes, restores revision 8 after restart, and releases both ports and the lease. The browser cross-port test confirms that a forwarded loopback cookie cannot recover or authorize the dashboard session.

Adversarial tests cover CSS writes/removals over 2 MiB separator runs, Unicode control/separator refusal, linear HTML indexing, changed-file-only indexing, and SIGTERM during startup import with lease cleanup. These scanner and startup checks have separate 2.5-second process budgets; those are test timeouts, not runtime preemption. Both HTTP origins remain usable with 48 unauthenticated sockets held open. Preview transformations are reused across query variants and invalidated when edits are saved. Malformed refresh tags, unresolved URLs and Unicode search offsets are also covered.

CSS tests verify replacement after comments, @import/@charset and broken-string lines, and refusal of unbalanced authored quotes/brackets. The no-hit search test completes two searches over each of two 15-file, roughly 30 MiB Unicode inputs in 1.08 seconds under a 2.5-second process budget. Search folds ordinary runs natively, handles full-fold exceptions explicitly and maps actual match boundaries to original offsets, rejecting matches inside an expansion.

All **50 runtime regexes** are centralized in an inventory. Every expression runs on **22 adversarial input shapes** under its own three-second child-process budget. A source check rejects regexes outside that inventory. Tests also cover the fixes for repeated attribute-tail scanning and overlapping CSS declaration parsing. See [REGEX-AUDIT.md](REGEX-AUDIT.md) for scope and limits.

The Chromium referrer tests inspect browser-prepared HTTPS request headers using DevTools Fetch interception, including imported document/element policy overrides, redirects and SVG. Nineteen fixtures cover malformed comments, declarations, processing instructions, end tags, raw-text closing tags, SVG/MathML content, dropped raw-text elements and namespaced meta tags, plus stylesheet and navigation links. Requests prepared by these fixtures contain no Referer header; dropped raw-text elements leave their hidden requests inert. The test fulfills requests locally before TLS setup. An attempted test with a real HTTPS receiver could not initialize TLS because the container lacked Chromium's NSS soft-token library, so real TLS receiver behavior is not verified by these results.

Synthetic MCP clients do not verify real host/model behavior. Claude Code, Codex and DeepSeek Harness were successfully tested against an earlier build; those results do not verify this exact build. Windows runtime, PowerShell execution, macOS filesystem semantics and cross-account access are not established by this Linux run. Automated tests do not replace an independent security assessment. Same-user processes can act as the user.

Saved-state migration refuses when it cannot verify the old source fingerprint or recover a revision-zero snapshot. Preview does not execute scripts, drops malformed opening tags, requires UTF-8 for SVG and may omit escaped CSS resource URLs. Export preserves original bytes.
