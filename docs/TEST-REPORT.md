# Site Studio 0.1.2 test report

On 2026-10-02, a Linux verification run passed **225/225 tests in 14 files**, with zero failures, skips or cancellations, in 63.86 seconds. It used Node.js 22.19.0 and headless Chromium with DISPLAY unset. See [TESTING.md](TESTING.md) for reproduction commands, optional screenshots and lifecycle records, and reproducible archive checks.

**The recorded browser run required Chrome's sandbox to be disabled in its container.** It explicitly used SITE_STUDIO_CHROME_NO_SANDBOX=1, which adds --no-sandbox and --no-zygote. These results do not verify Chrome sandbox behavior. Without that opt-in, the test harness leaves both sandboxing and the zygote enabled. Browser shutdown is bounded and completes before the other test HTTP servers close.

The suite exercises real stdio processes, two-page editing and confirmed export, browser controls, session isolation, preview capabilities, storage and validation failures, and deterministic archives. The lifecycle preserves original and binary bytes, restores revision 8 after restart, and releases both ports and the lease. The browser cross-port test confirms that another loopback port can receive a preview cookie at its matching path and use it for preview reads, but cannot recover or authorize the dashboard session. Separate tests require an authenticated, same-origin POST to issue that cookie and refuse missing, incorrect or duplicate cookies. A copied preview URL alone grants no access.

Adversarial tests cover CSS writes/removals over 2 MiB separator runs, Unicode control/separator refusal, linear HTML indexing, changed-file-only indexing, and SIGTERM during startup import with lease cleanup. These scanner and startup checks have separate 2.5-second process budgets; those are test timeouts, not runtime preemption. Both HTTP origins remain usable with 48 unauthenticated sockets held open. Preview transformations are reused across query variants and invalidated when edits are saved. Malformed refresh tags, unresolved URLs and Unicode search offsets are also covered.

CSS tests verify replacement after comments, @import/@charset and broken-string lines, and refusal of unbalanced authored quotes/brackets. The no-hit search test completes two searches over each of two 15-file, roughly 30 MiB Unicode inputs in 1.73 seconds under a 2.5-second process budget. Search folds ordinary runs natively, handles full-fold exceptions explicitly and maps actual match boundaries to original offsets, rejecting matches inside an expansion or surrogate pair and retrying overlapping candidates after rejection. Dense full-fold search over five 2 MiB files for each of sharp-s, Greek sigma and Cherokee completes in 2.52 seconds under a four-second child-process budget. CSS fixtures also verify escaped delimiters outside strings.

All **53 runtime regexes** are centralized in an inventory. Every expression runs on **22 adversarial input shapes** under its own three-second child-process budget. A source check rejects regexes outside that inventory. Tests also cover the fixes for repeated attribute-tail scanning and overlapping CSS declaration parsing. See [REGEX-AUDIT.md](REGEX-AUDIT.md) for scope and limits.

The Chromium referrer tests inspect browser-prepared HTTPS request headers using DevTools Fetch interception, including imported document/element policy overrides, redirects and SVG. Nineteen fixtures cover malformed comments, declarations, processing instructions, end tags, raw-text closing tags, SVG/MathML content, dropped raw-text elements and namespaced meta tags, plus stylesheet and navigation links. Eleven additional shapes cover SVG foreignObject/desc, MathML, malformed self-closing markup, ignored closing tags, XHTML roots and prefixed SVG roots with unprefixed title/style elements. Preview URLs contain only a routing ID, and the browser cannot read the HttpOnly capability cookie. Requests prepared by these fixtures contain no Referer header or read capability; dropped raw-text elements leave their hidden requests inert. The test fulfills requests locally before TLS setup. An attempted test with a real HTTPS receiver could not initialize TLS because the container lacked Chromium's NSS soft-token library, so real TLS receiver behavior is not verified by these results.

Synthetic MCP clients do not verify real host/model behavior. On 2026-10-02, Claude Code, Codex and DeepSeek Harness passed editing/checkpoint proofs on the 0.1.2 candidate ZIP with SHA256 `df808d1b0cd3c775822a672693230cb084b85f5570fa3bde21506800bec0c394`. The human link was redeemed before model work, originals stayed unchanged and no export was requested. Codex 0.158.0 also loaded all 16 plugin tools from a scrubbed environment. These historical proofs identify their exact bytes; later fixes need their own artifact checks. Windows runtime, PowerShell execution, macOS filesystem semantics and cross-account access are not established by this Linux run. Automated tests do not replace an independent security assessment. Same-user processes can act as the user.

Saved-state migration refuses when it cannot verify the old source fingerprint or recover a revision-zero snapshot. Browser tests verify legacy HTML quirks mode, named attribute entities, and SVG CDATA styling with Illustrator-style internal namespace declarations. XML tests bound literal entity expansion and do not resolve external, recursive or parameter entities. Preview does not execute scripts, drops malformed opening tags, requires UTF-8 for SVG and may omit escaped CSS resource URLs. These conservative rewrites can change malformed content; they are not a general HTML/XML sanitizer. Export preserves original bytes.

The long-query regression searches 2 MiB of sharp-s and a dense ligature input using rejected 8,191-character queries under a three-second child-process budget. A deterministic comparison checks 12,000 generated search cases. Fifteen dense Unicode inputs containing isolated newer-case characters have a separate four-second budget. The preview-amplification regression runs a roughly 10 KiB entity-heavy SVG in a child with a 128 MiB V8 old-space limit, a three-second deadline and less than 128 MiB peak RSS growth. Other fixtures exercise UTF-8 expansion, output, attribute and token limits and failure caching across repeated query variants. These are bounded workload checks, not a universal process-memory guarantee.

Real Chromium compares eleven semicolonless attribute cases against its own HTML parser. Another loopback HTTP server shadows, evicts and overwrites preview cookies: the first two failures recover automatically, a further failure stops automatic retries, and manual Refresh preview restores access. Dashboard reload rotates the capability and routing prefix. Controller authorization remains independent of these cookies. Continuous same-host interference remains outside the availability guarantee.

Packaging tests launch the configured server using literal folder arguments containing spaces and shell metacharacters, preserve Codex sample defaults, compare Desktop and Code launch definitions and test the fixed build clock. Claude Code 2.1.284 strict manifest validation and mcpb 2.1.2 manifest validation pass. Native Desktop installation, production publisher trust, Registry publication and directory acceptance are not established by these checks; see [CLAUDE-INSTALL.md](CLAUDE-INSTALL.md).

The current suite also verifies authenticated dashboard link replacement, revocation of old dashboard and preview credentials, dense-page preview rendering, individual oversize-attribute omission and visible preview failures. Browser fixtures wait for the new document’s load event and asynchronous interception completion, isolate favicon cookie traffic, and check that manual repair clears its stale warning. Absolute configured paths are required. Release-tool fixtures refuse a mismatched remote tag or download and detect private-key headers in compressed archives, unlisted files and reachable Git blobs. These fixtures use synthetic identities and do not publish or authenticate a production release.

Crash-recovery tests kill a real MCP process after a saved checkpoint, restart without manual lease removal, preserve a live owner, simulate PID reuse and a previous boot, recover abandoned recovery claims, and race four restart attempts while allowing one writer. Special lease files refuse without blocking. Linux process creation, boot and PID namespace identities were exercised. Additional regressions refuse mismatched host/namespace/platform scopes, preserve abandoned claims under an injected paused-recoverer race, keep live or unverifiable temporary files, tolerate cleanup races, and permit exactly one owner in twelve two-starter runs. A real POSIX ps fixture forces the macOS branch under different owner/contender TZ settings on Linux; this is not native macOS qualification. Native macOS and Windows PowerShell execution still need qualification. Older unscoped leases require manual verification before removal.

Dashboard renewal tests cover double-clicks, reload and an explicit browser move with a retained link. The referrer fixture deliberately adds a subframe request and counts only top-frame traffic; three consecutive browser-file runs passed with two CPU workers active. An earlier run exposed a separate navigation-test race, which was corrected. These load checks do not replace quiet-host performance gates.
