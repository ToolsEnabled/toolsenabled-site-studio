# Security boundaries

Pause, resume, undo, redo, checkpoint restore/delete and export are **not available as MCP tools** and **require the dashboard session**. No MCP tool starts capture, publishes or deploys content.

At each launch the process prints a one-time dashboard link with its secret in a URL fragment. The page removes that fragment before exchanging the secret by an Origin-checked JSON POST. The returned per-launch token is held only in sessionStorage, scoped to the exact origin including port. Status, events and controls require it in the X-Site-Studio-Control header. No GET response reveals a session token, and cookies never authorize dashboard status, events or controls. Replayed launch secrets are refused. Keep startup diagnostics private. Restart to obtain a new link if the browser session is lost.

Every human control also requires the expected loopback Host and exact Origin, JSON content and the current revision. Export needs explicit confirmation and uses the destination configured at startup. Correct Origin and JSON, with or without a stolen loopback cookie, are insufficient. The static preview uses a different loopback origin. An Origin-checked POST to /api/preview-session, authenticated by the dashboard's session header, issues a separate per-launch read capability as a host-only HttpOnly, SameSite=Strict session cookie. Its path is restricted to a random preview prefix. The preview URL contains only that routing prefix, never the capability. Missing, wrong or duplicate capability cookies are refused. The controller's /site/ alias is refused. Preview capabilities never appear in MCP results, response bodies or JavaScript-accessible storage; cookies grant only preview reads.

Preview cookies use HTTP on loopback and are not port-scoped. A browser request to another 127.0.0.1 port with the same cookie path can expose the read cookie to that server. This does not disclose or authorize the dashboard token, which is scoped to the exact origin in sessionStorage and required in a header. Treat other local processes as outside this protection boundary. The Host check prevents remote use through DNS rebinding.

Preview responses use Referrer-Policy: no-referrer. Rewriting removes recognized document and element referrer overrides, rebuilds all opening tags with escaped attributes, and escapes retained HTML RAW text. This is defense in depth, not a general HTML/XML sanitizer or a guarantee against every browser parser recovery. With --allow-external, permitted resources can still observe ordinary request metadata and any imported content that names them. A Referer cannot disclose the preview read capability because that capability is absent from the URL. Agent-authored fragments are canonicalized and cannot author these overrides. External resource loading requires explicit startup opt-in.

This boundary reduces accidental authority sharing. **A process running as the same user can still act as the user**, including reading process diagnostics or memory, driving the browser or changing files directly. Session capabilities and the optional host hook are not a sandbox against that process. They do not identify whether a physical human clicked a button. Restrict the MCP host's other tools and use OS isolation for stronger separation.

Source and state roots must be separate. File operations reject traversal, symbolic links, hard links, special files and ambiguous paths. A state lease coordinates cooperating Site Studio processes; an export lease serializes cooperating exports to a destination. Startup installs signal handlers before import and yields between bounded file operations and around the initial commit. SIGTERM cancellation releases the acquired lease; an in-progress synchronous file operation finishes before the signal is handled. There is no automatic stale-lease takeover. A process with permission to concurrently replace path ancestors remains outside the filesystem trust boundary. Network filesystems and arbitrary direct writers are unsupported.

New HTML/SVG/CSS is checked by conservative allowlists and reference rules. Imported scripts and source bytes are preserved for export but run inert in preview. Preview CSP and iframe sandbox disable scripting, frames and forms. Preview rewriting removes recognized HTTP-equivalent meta tags, referrer meta tags and base overrides, and drops malformed opening tags. Parser differences can expose markup outside those recognized tokens; CSP base-uri and the sandbox remain the enforcement against base overrides and automatic refresh. SVG preview requires UTF-8 and uses XML tokenization without HTML RAW rules. CDATA is retained; DOCTYPE declarations are removed after resolving at most 128 simple literal internal entities of at most 4,096 characters each, under an 8 MiB decoded-text budget. External, parameter and recursive entities are not resolved; unresolved references render as literal text. Other encodings remain preserved for export but cannot be previewed. HTTPS external static resources require explicit startup opt-in. Model output is never executed as a command. Runtime includes no provider client, credentials, network fetcher or deployment code.

Both listeners use two-second incomplete-request and socket-idle timeouts, a one-second keep-alive timeout and no global connection-count cap. The authenticated event stream is exempt from socket-idle timeout and limited to eight clients. Refused requests close their connection. These controls avoid the previous pre-authentication slot lockout; they do not guarantee availability against OS resource exhaustion.

CSS reads and rule mutation share a linear scan. HTML indexing uses per-tag stacks and re-indexes only the edited file. CSS edits refuse control, formatting and Unicode separator characters other than ordinary space. Every runtime regex is inventoried and tested on adversarial inputs under a child-process time budget; see [the regex audit](docs/REGEX-AUDIT.md). Those budgets are test gates, not runtime preemption. Preview transformations are cached per frozen snapshot file under a 64 MiB buffer budget; a commit invalidates the cache.

State writes use a flushed temporary file and atomic rename; the directory is flushed where supported. A post-rename directory-sync failure reports a durability warning without pretending the edit was rejected. Export stages a complete tree and retains the original as a backup when replacing it. Ordinary promotion/persistence failures roll back; a process or machine crash between directory renames may require restoring the retained backup manually. Keep independent backups for valuable sites.

Read the included [test report](docs/TEST-REPORT.md) and [reproduction commands](docs/TESTING.md). The included evidence covers synthetic protocol clients and headless Chromium on Linux with Chrome sandboxing disabled in this container. Referrer tests inspect browser-prepared HTTPS request headers through DevTools interception, including redirects and SVG; a real TLS receiver could not run here because the installed Chromium dependencies lack the NSS soft-token library. It does not substitute for an independent security review or real-host qualification.
